opsward.memory_audit#

Memory audit: fleet-wide rules stranded in project-local auto-memory, and who should own them.

Claude Code’s auto-memory is keyed by working directory: a feedback memory written in one project loads only in sessions started there. A rule that holds for every project is stranded in that one. This audit lists every memory of the chosen kinds, then for each one:

  • scope: project or fleet, with the reason (classify(), a heuristic; pass classify= to use a judge instead);

  • duplicates: memories in other directories that say nearly the same thing (similarity(), lexical, replaceable);

  • owner: for a fleet-wide one, the installed skill whose name and description match it best, else ~/.claude/CLAUDE.md, and whether the owner already says it;

  • stub: a memory that only says it moved elsewhere, listed for deletion.

Report-only: it never writes, moves or deletes a memory. The user curates the table.

>>> parse_frontmatter("---\nname: x\nmetadata:\n  type: feedback\n---\nbody")
({'name': 'x', 'type': 'feedback'}, 'body')
