opsward.weekly#

The weekly look: the agent setup’s five numbers, against last week, and one proposed change.

The setup-self-improvement loop asks for one improvement a week, chosen from five numbers and passed through a human gate. This module prints the numbers; the user picks the change. It only reads, and the only thing it writes is its own history (one JSON file per run).

The five numbers, over the last days (30 by default):

  1. Search before write: of the new source files an agent wrote, the share written after the session had searched what the fleet already has (an Explore agent, a search skill such as fleet-protocol, or ir/projreg/priv find/gh search in Bash). Local greps are counted beside it as context: agents run them in nearly every session. A file counts as new when the session writes it without having read or edited it first.

  2. Skills never invoked: the share of installed skills no session invoked (with the invocation count per skill). Never-invoked skills are candidates for name-only or deletion, not for a longer description.

  3. CLAUDE.md before edit: of the packages a session edited, the share whose nearest CLAUDE.md the session had loaded first (its cwd is inside the package, or it read the file before the first edit).

  4. Component issues per week: issues titled Component: ... the owner filed.

  5. Corrections written back: writeback-seen events over the triggers (trigger-prompt, trigger-fix-commit) in the fix-at-source hook’s event log.

Only metadata is read: tool names, file paths, skill names, timestamps. Never prompt or file text. Every source is a keyword argument (sessions, skills_dirs, search, events, history), so a caller or a test can point it elsewhere.

>>> NUMBERS[0].key, NUMBERS[1].better
('search_before_write', 'lower')
